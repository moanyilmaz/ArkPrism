\section{Implementation}
\label{sec:implementation}

\mytool is implemented in TypeScript as a command-line analyzer. It reuses ArkAnalyzer's Scene, ArkIR, call graph, and pointer-analysis interfaces, and extends HapFlow's IFDS client with source-binding and continuation transfer. The analyzer processes one project per isolated frontend Scene and emits machine-readable JSON together with optional DOT evidence graphs.

\subsection{Versioned Source Specifications}

The detector configuration contains 716 records across 58 system-package groups: 453 namespace calls, 213 manager/receiver operations, and 50 executable properties. The records represent 710 unique package--namespace--member identities, 38 privacy categories, and 74 permission labels. Each record stores its access form and, where applicable, the factories that establish receiver ownership. A namespace-constrained export map relates historical modules to their corresponding \texttt{@kit.*} exports without treating an entire kit as one namespace.

The taint query is deliberately smaller. It contains 257 privacy-data rules whose API-20 declarations expose a concrete return or callback carrier, plus two explicitly modeled framework-input rules. Each rule records source kind, SDK owner, signature metadata, carrier form, and callback/parameter positions when required. Structural validation rejects missing source kinds, ambiguous owners, non-concrete return types, malformed callback positions, and unresolved carrier types. All 257 privacy-data rules resolve uniquely under API-20; 249 also resolve under the API-17 SDK used by HapBench, with the remaining eight retained as explicit version differences rather than redirected to same-named declarations.

\subsection{Source-Binding Engine}

The detector indexes rules by package and namespace before scanning executable ArkIR statements. It normalizes import aliases and documented exports, classifies each candidate as namespace call, assigned call, manager call, or property read, and recovers compound namespaces when lowering assigns a prefix such as \texttt{request.agent} to a temporary. For manager calls, a backward definition walk of at most eight steps searches assignments, factory invocations, exact SDK types, and resolved call targets. The selected ownership evidence is stored with the occurrence. Package-only and member-only candidates are rejected.

The IFDS source loader first uses exact SDK targets. An unresolved target can match only when member, arity, normalized parameter types, owner evidence, and any event literal agree with the rule. This prevents generic members such as \texttt{on}, \texttt{get}, and \texttt{create} from inheriting an unrelated source identity. Source creation then follows the rule's carrier contract: direct results seed the assigned value, callback sources seed only the designated payload parameter, and explicit framework inputs seed their specified argument.

\subsection{Continuation-Aware IFDS}

The solver derives interprocedural targets from the Scene and pointer information. It resolves function-valued arguments on invocation statements, including assigned Promise calls, but creates an executable callback edge only for a configured callback source, a known ArkUI event, a witnessed platform-task contract, or a witnessed Promise fulfillment handler. Platform-task contracts constrain the API owner and callback position. Promise contracts additionally distinguish Promise-returning overloads from callback overloads and reject application-defined methods named \texttt{then}.

IFDS facts include the structured ArkIR value and access path, carrier state, and immutable source binding. At a Promise success edge, the transfer requires a Promise-payload fact rooted at the receiver and re-roots it to the first success-handler parameter. Return flow re-roots only values that depend on the incoming payload, which supports sequential continuations and Promise flattening while stopping constant-return transforms. Rejection handlers, unrelated aliases, and non-Promise owners receive no payload fact. Native ArkIR use edges handle \texttt{await}; a separately labeled bounded analysis is used only when callback or Promise relations are absent from ArkIR.

The implementation preserves initializers, closure environments, exceptional successors, constant-index access paths, and source-distinct fact identity. It analyzes all sources jointly; batching is available only as an explicit resource fallback. Complete, resource-bounded, and failed runs are separate states, and only complete runs contribute negative evidence.

\subsection{Evidence Assembly}

Detector-local tracing classifies nearby log, UI, storage, network, return, intent, and sharing operations for audit context. These observations remain distinct from configured IFDS sinks. Each query path records its source binding, source kind, sink endpoint, complete statement sequence, producing analysis, and Promise transfer derivations. A privacy-data path is linked to a detector occurrence only when project, normalized source location, and API identity agree. Framework-input and unlinked query paths remain separate records. This partial join prevents a project-level path from being attached to every privacy API in the same project.
