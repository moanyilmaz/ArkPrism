\section{Discussion}
\label{sec:discussion}

\subsection{Implications of the Results}
The results show that \mytool scales to a large \openharmony corpus and recovers useful evidence for privacy-sensitive API recognition and information-flow subgraph mapping. The strongest engineering evidence is end-to-end coverage: all 1,015 projects produced reports, and each detected API usage received a non-empty call-chain entry. Package-aware matching substantially reduces the noise of raw method search, while the ArkPrismBench stratified benchmark confirms detection accuracy across all output levels, including zero-output projects.

The results should be interpreted at the evidence level. A taint flow to a log or UI display is not automatically a privacy violation; a local fallback chain is not a complete lifecycle path; the benchmark covers only 16.3\% of the corpus and cannot guarantee zero false negatives in unsampled projects (Section~\ref{subsec:app_manual_audit}). \mytool is designed as an audit-support system that preserves API, call-chain, sink, taint, and metadata evidence for downstream auditors. The design also exposes natural ablation points---package-family normalization, namespace-member alias tracking, indirect-call recognition, typed callback edges, lifecycle modeling, and context-sensitivity level $k$ can each be disabled independently, supporting both high-recall marketplace auditing and stricter continuous-integration settings.

\subsection{Threats to Validity}
\textbf{Benchmark and corpus validity.} The ArkPrismBench stratified benchmark addresses purposive-sampling bias by including zero-output and low-output projects, but covers only 16.3\% of the corpus; the micro-benchmark provides controlled pattern-level validation but uses hand-crafted cases. The corpus contains real projects but also many demos and samples, which can inflate counts for sensors, camera, network, and clipboard APIs. Additional evaluations on marketplace and industrial corpora would strengthen external validity.

\textbf{Analysis validity.} Call-chain validity is limited by the separation of framework-entry, initialization, unknown-entry, and local fallback chains---chain-entry coverage should not be read as complete framework-entry recovery. Taint validity depends on SDK signature resolution, pointer analysis, and callback modeling; callback-specific flows still require manual inspection. Lifecycle modeling does not increase taint flow counts even at Level~2 because IFDS's may-analysis explores all inter-procedural paths regardless of execution order; only 3/302 projects with taint flows show any count change (each losing one flow from more precise call resolution). The lifecycle model's contribution is instead in collaboration behavior (+44.2\% in quantity, 260$\to$375 projects; precision not systematically audited) and call graph enrichment (+32.6\% average CG node increase). Context-sensitive CG ($k=1$) provides marginal precision improvement at 5.02$\times$ overhead (96.3\%/91.6\% vs.\ 97.8\%/91.1\%), with recall affected by 5 estimated false negatives from \texttt{@kit.*} namespace imports not currently matched by IFDS source resolution. The lifecycle model's cross-layer transitions depend on ability/component class discovery, which may miss custom subclasses.

\textbf{Rule and temporal validity.} The sensitive API rule file reflects our current understanding; some entries may be over- or under-inclusive, affecting both detection and benchmark construction. The results are tied to a fixed corpus, rule set, and SDK version---future comparisons should report the analyzed configuration explicitly.

\subsection{Limitations}
\mytool is static and source-based. It cannot observe runtime-only configuration, dynamically loaded modules, server-provided policy, platform permission prompts, or user consent. It also cannot determine whether a privacy-policy disclosure is adequate. The graph it produces is an evidence artifact for audit, not a final compliance verdict. Dynamic confirmation, policy-text analysis, and marketplace-scale deployment are natural extensions.
