\section{Related Work}
\label{sec:related}

\subsection{Mobile Privacy Sources and Sinks}

Source and sink definitions determine the behaviors visible to a mobile taint analysis. Android work has derived these definitions from permissions, framework behavior, and API documentation, including Stowaway, PScout, SuSi, Axplorer, and FUSE~\cite{stowaway,pscout,susi,axplorer,fuse}. Other systems connect code-level flows with permissions and privacy policies~\cite{appaudit,appintent,policheck,ppchecker}. These studies establish that API classification is a semantic input, not a neutral list of member names.

ArkPrism addresses a different but related step: binding a configured OpenHarmony source to its owner and data-carrying value in ArkTS. HapFlow resolves namespace--method entries to SDK declarations and uses the resulting signatures as IFDS sources~\cite{hapflow}. This design is effective for source forms represented by the schema. ArkPrism retains signature resolution but adds witnesses for package re-exports, executable properties, factory-returned receivers, and compound IR aliases. Its contribution is therefore not a rejection of method signatures; it is an evidence-carrying binding between the signature-level identity and the concrete source carrier.

\subsection{Implicit and Asynchronous Execution}

Mobile analyses recover control flow that is absent from ordinary calls. Android systems model lifecycle, callbacks, and inter-component communication through dummy mains, framework summaries, callback mining, and ICC resolution~\cite{comdroid,chex,epicc,ic3,iccta,didfail,raicc,edgeminer,arzt14}. Hybrid-app analyses additionally bridge native and script execution~\cite{lee16,bridgescope,babelview,eoeidroid}. This body of work shows that implicit edges must be constrained by platform semantics to avoid turning every registered callback into an execution path.

Promise and event analyses make a complementary distinction between scheduling and data transfer. Executes-before analysis models task-post order~\cite{executesbefore}; PromiseKeeper represents fulfillment, rejection, and chained reactions explicitly~\cite{promisekeeper}; WEMINT applies API-specific asynchronous rules to mini-program ASTs~\cite{wemint}. ArkPrism brings these obligations into ArkTS IFDS. An execution witness admits the continuation edge, while a carrier fact identifies the fulfilled value. Promise ownership, handler position, alias identity, and payload-dependent return then determine whether that fact crosses a continuation.

\subsection{OpenHarmony Analysis Infrastructure}

ArkAnalyzer provides the source-level representation, control-flow graph, call graph, and analysis APIs used by ArkTS clients~\cite{arkanalyzer}. APAK extends this foundation with a context-sensitive pointer analysis and ArkTS-specific heap and closure modeling~\cite{arktsPointer}. ArkPrism consumes these call-target and receiver facts when resolving source ownership. Neither framework defines a privacy source query by itself.

HapFlow is the closest end-to-end baseline because it accepts ArkTS projects and answers the same source-to-sink reachability query~\cite{hapflow}. ArkPrism extends that analysis boundary with source binding, continuation-carrier transfer, receiver-refined dispatch, and evidence retention. HarmonyFlow instead analyzes compiled Ark Panda IR and focuses on pointer and call-edge recovery~\cite{harmonyflow}. HScope also operates on OpenHarmony bytecode, using abstract interpretation to resolve indirect calls and inter-component communication for privacy-leak detection~\cite{hscope}. These bytecode analyses are complementary to ArkPrism's source-level goal: preserving ArkTS package, receiver, source-location, and carrier evidence before and during taint propagation.

Android analyzers provide broader methodological reference points. FlowDroid, Amandroid, DroidSafe, IccTA, HornDroid, COVERT, and PacDroid explore different combinations of lifecycle, context, points-to, and inter-component precision~\cite{arzt14,wei2018amandroid,gordon2015droidsafe,iccta,horndroid,covert,pacdroid}. Their input languages and framework models differ from ArkTS, so we use their design principles rather than compare published numbers under incompatible queries.

\subsection{Evaluation of Static Analyses}

ReproDroid shows that analyzer comparisons require a common query, benchmark set, and execution environment~\cite{reprodroid}. TaintBench provides machine-readable real-world flow oracles with expert review~\cite{taintbench}; mutation-based evaluation exposes unsound choices that fixed suites may not cover~\cite{muse}. Our evaluation follows these principles by running the complete HapBench artifact under one query, retaining negative cases, auditing endpoint pairs, constructing source-first exact-location labels independently of detector output, and using semantic mutations to isolate Promise ownership, execution, and carrier transfer.
