\subsection{Lifecycle-Oracle Sensitivity}
\label{subsec:app_oracle_sensitivity}

The primary evaluation preserves all published/source-annotated HapBench labels. We additionally define a strict executed-order contract for the three disputed lifecycle cases: an override does not execute its parent body without an explicit \texttt{super} call; an instance field does not cross framework-created instances without a same-object witness; and a UI callback occurring after initial ability creation does not feed an earlier \texttt{onCreate} without an explicit later-creation edge. This contract relabels \texttt{ActivityLifecycle4}, \texttt{BackupExtensionAbility}, and \texttt{Button1} as negative and changes no other case.

\subsection{Source-first Benchmark Protocol}
\label{subsec:app_manual_audit}

ArkSourceFirst60 is selected before the evaluated detector run. Projects are partitioned by source-tree size and by whether their imports are compatible with the frozen sensitive-API rules; deterministic hash ordering selects ten projects from each of the six strata. The manifest stores the selection seed, source-tree fingerprint, rule hash, and package-migration hash. Candidate discovery parses executable member accesses and import bindings, but it neither reads a \mytool report nor assigns a gold label.

Manual review accepts an occurrence only when its executable source context establishes the configured package/namespace/member and access kind through an import, SDK receiver type, constructor, manager/factory definition, or executable property read. It rejects comments, strings, declarations, same-name application methods, and unrelated library/controller receivers. The delivered gold file contains 90 accepted occurrences; a companion decision file preserves all 101 accept/reject judgments, including the 11 high-confusion negatives. An integrity test rehashes every source file, validates every exact line and canonical rule key, and rejects duplicate occurrence identities. Evaluation joins detector and gold records on project, normalized file, exact line, canonical API, and access kind.

\subsection{High-output Stress-audit Decision Rule}

The 120-project audit labels an item at project--namespace--member level. A report is accepted only when the recorded source context contains an executable access matching the configured API and one of the following identity witnesses:

\begin{compactitem}
  \item an imported namespace or package alias invokes the configured member;
  \item a manager/helper receiver is connected to its configured factory by a visible definition or field assignment;
  \item an SDK receiver type identifies the configured namespace; or
  \item an executable field/property access is declared as a property source in the fixed rule set.
\end{compactitem}

Comments, string literals, declarations without access, unrelated application methods with the same final token, and ambiguous method-only matches across multiple package namespaces are rejected. For every accepted key, the artifact stores project identifier, normalized package/namespace/member, access kind, source file and line, and a bounded source snippet. Precision is computed over the 666 project--API keys.

The enriched construction file contained 1,533 report-derived rows, including repeated rows that pointed to the same source evidence. The delivered \texttt{top120\_source\_audit\_annotations.json} canonicalizes them to the 666 audited project--API keys, removes detector-internal fields, and does not contain occurrence-precision, false-negative, or recall counters. Its declared scope is \texttt{output\_selected\_precision\_audit}; both \texttt{occurrencePrecisionDefined} and \texttt{recallDefined} are \texttt{false}. This prevents the source-evidence artifact from being mistaken for an exhaustive occurrence-level or source-first oracle.

The companion integrity audit independently resolves each record against the delivered source tree and final detector rules. It checks project and file existence, positive line bounds, member text on the recorded line, nonempty snippets, and package/namespace/member compatibility under the same migration and normalization contract as the detector. All 666 records pass these structural checks. This check establishes artifact referential integrity; it does not replace the source-review decision or convert the audit into a recall benchmark.

\subsection{Artifact-to-Paper Traceability}
\label{subsec:app_traceability}

The artifact provides ArkSourceFirst60's selection manifest, review decisions, occurrence gold set, and integrity evaluator; the 64-case ArkIdentityBench progression oracle; machine-readable oracles for all 67 HapBench and 48 ArkAsyncBench cases; and raw output for every evaluated configuration. The evaluators derive confusion matrices, construct/category metrics, paired outcomes, and runtimes. Figure~\ref{fig:eval_hapbench} is generated from evaluator JSON rather than transcribed from the paper. Corpus tables and figures consume one process-isolated run of the final build; change-impact overlays are rejected by the release summarizer. The run manifest and batch summary record the project inventory, analyzer revision and build hash, rule and SDK fingerprints, command line, resource bounds, completion state, and the explicitly excluded partial project.

The corpus audit checks three invariants before aggregation: each configured-query path has resolvable source and sink endpoints, each path carries an \texttt{ifds}, \texttt{async\_supplement}, or \texttt{both} provenance tag, and every detector-to-path link references valid records with compatible source evidence. Detector-local sink records and configured-query paths remain separate when this conservative join cannot be established. Figure companion JSON files retain the input manifest and computed values so that figures, tables, and prose cannot silently use different runs.
