# ArkPrism 实现说明（归档叙述版）

本文件保存一份自然语言版本的实现说明，强调“分析器实际如何工作”，不展开代码级细节。

## 1. ArkPrism 在做什么

它并不是简单扫描“项目用了哪些隐私 API”。它要恢复的是一条完整行为链：

- 哪个页面或哪个入口触发了隐私访问
- 中间经过了哪些业务方法、回调或异步逻辑
- 数据之后去了哪里
- 多类隐私数据是否在同一业务逻辑里协同出现

## 2. 它为什么要自己增强调用链

真实 ArkTS 项目里，大量逻辑藏在：

- ArkUI 回调
- 匿名函数
- `%AM...` 编译后方法
- Promise 回调
- SDK API 终点

这些位置如果只靠原生调用图，链路很容易断掉。ArkPrism 因此会额外补：

- 函数参数回调边
- `%AM` 兜底回调边
- Promise 回调边
- 可达域内的显式调用边

最后再从隐私 API 反向追到入口。

## 3. 它不是只找 API，而是在做行为解释

一条恢复出来的链路，还会继续补这些信息：

- API 是否位于条件判断或异常处理里
- 哪个方法最像真正的业务动作
- 数据有没有继续流到网络、存储、界面、日志或返回值
- 当前项目里是否存在多类隐私能力的协同使用

因此最终结果比“命中了哪些 API”更接近真实审计视角。

## 4. 当前实现的边界

当前版本仍有明确边界：

1. 数据汇聚是轻量跟踪，不等于完整污点分析。
2. 权限分析只提取声明，不做自动合规判定。
3. HapFlow 是可选阶段，依赖 SDK 和规则配置。

## 5. 一句话概括

ArkPrism 的实现可以概括为：

先用结构化静态分析定位隐私触点，再用增强调用链恢复真实执行路径，随后补上数据去向、多源协同和权限背景，并在条件允许时用 HapFlow 提供更精确的过程间数据流证据。
