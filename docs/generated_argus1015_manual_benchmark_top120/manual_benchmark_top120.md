## Scope and Method

This benchmark is a manual source-code review benchmark. Scripts were used only to collect candidates and source locations; labels were assigned after inspecting source context. The full automatic benchmark is not used as the final ground truth here.

- Candidate collection is not treated as ground truth. ArkPrism reports and source searches are used only to locate code that must be manually reviewed.
- A method is accepted into gold only when the source context contains an executable sensitive API call or field access matching config/sensitive_apis.json at namespace+method level.
- Comments, string literals, UI constants, ordinary same-name methods, and unrelated enum/constants are rejected unless the API access occurs inside an executable template expression.
- For member calls through manager/helper/wrapper receivers, the surrounding source and ArkPrism IR evidence must jointly support the sensitive API receiver, for example calendarMgr.getCalendar(), helper.createAsset(), request.agent.create(), or userAuth wrapper calls.
- Recall in this benchmark is measured against the manually accepted project-level namespace+method gold set for these 120 projects; this does not claim full 1015-sample manual perfection.
