\title{\mytooltitle}

\begin{abstract}
Static taint analysis can track privacy data only after a platform source has been identified and bound to the program value that carries its output. This prerequisite is difficult in \openharmony applications. ArkTS APIs are accessed through evolving package exports, factory-returned managers, properties, and compiler-generated aliases, while callbacks and Promise continuations deliver data through values that are absent from a direct-call signature. A missed binding removes the initial taint fact; an unsupported binding introduces flows from unrelated application code.

We present \mytool, which makes \emph{privacy-source binding} an explicit analysis stage. For each source candidate, it resolves $\langle identity, carrier, witness\rangle$: the canonical platform operation, the value that carries privacy data, and the evidence supporting both decisions. Witness-guided resolution combines package exports, receiver origin, access form, SDK declarations, and IR aliases. Continuation-aware IFDS then preserves the bound carrier across ArkTS callbacks, Promise success handlers, and \texttt{await}; each reported path retains its source and transfer evidence for inspection.

On a source-first real-project benchmark, \mytool locates all 90 gold source occurrences and rejects all 96 same-name collisions. On the complete 67-case HapBench suite, it reaches 100\% precision and specificity and 97.09\% F1, improving specificity by 28.57 percentage points and F1 by 2.65 points over HapFlow. A targeted asynchronous benchmark attributes nine additional positive cases to Promise-carrier transfer without changing 24 matched negatives, and a mutation suite classifies all 24 Promise-boundary cases correctly. Manual inspection validates all 90 sampled real-project privacy-data paths. Across \CorpusProjects{} projects, \mytool identifies \CorpusApiOccurrences{} privacy-API usages and \CorpusPrivacyPaths{} privacy-data paths without resource fallback.
\end{abstract}

\section*{Data Availability}
The replication package contains the \mytool source and build scripts; API, source, sink, and package-migration rules; ArkSourceFirst60 and ArkIdentityBench; the Top-120 stress audit; HapBench, ArkAsyncBench, and ArkPromiseBench sources, oracles, and configuration outputs; the 120-path semantic review; and per-project results for the \CorpusProjects{}-project corpus. Run manifests bind each result to analyzer and frontend commits, rule hashes, SDK fingerprints, feature flags, and resource policy. Machine-readable results regenerate every table and figure. Dataset redistribution follows each constituent project's license; project identifiers and derived reports are supplied where source redistribution is restricted.
